Grassmannian EBR Chat-Code Porting Ledger¶

This engineering note records the ordered review and port of code fences in data/chats/Gemini_Quantum-Causal-Grassmannian-Monograph-Review_20261118-1629.md. The source-line column points to each fence’s opening line. The 64 blocks were extracted in source order to .tmp/chat-code-blocks/ with a numbered filename and a TSV manifest. Re-running the extraction from the source export reproduces that local working archive. The inventory contains 19 Lean, 3 Rust, 12 Python, 5 diff, 5 Markdown, 16 plain-text, 2 shell, 1 BibTeX, and 1 LaTeX block.

This is not an independent scholarly or experimental validation of the claims in the chat. The disposition terms mean:

  • Ported: corrected finite math or a working bounded implementation was added to the Signals source.

  • Reused: an existing Signals definition or test already owns the behavior; no duplicate declaration was added.

  • Replaced: an unverified heuristic was replaced by a deterministic reference implementation with tests.

  • Not adopted: narrative, incomplete, unverified, or unsupported code was retained only in the chat source and numbered local archive.

Extract And Apply CLI¶

The reusable parser is in src/transform_md/transform_md/transform_md.py and the CLI is src/transform_md/transform_md/chat_code_blocks.py; the workspace entry point is tools/extract_chat_code_blocks.py.

python3 tools/extract_chat_code_blocks.py extract data/chats/example.md \
  --destdir .tmp/chat-code-blocks --verbosity verbose

By default, output filenames start with their source-order sequence number, and the manifest is <destdir>/chatpatches.json. Set --no-sequence-prefix to use the source line number in filenames, or pass --manifest to choose a manifest path. --force replaces an existing extraction; without it, the tool reuses an intact manifest only when the source hash and extraction options match.

Only fences labelled diff or patch are eligible for application. Every patch is hash-checked and run through git apply --check --recount before application. Progress is written into the JSON manifest after each patch, so an already-applied block is not blindly applied twice.

python3 tools/extract_chat_code_blocks.py apply \
  --manifest .tmp/chat-code-blocks/chatpatches.json -i

Interactive mode pauses before each patch and offers retry, skip, or quit when an applicability check fails. A noninteractive failure saves the failing block and stops. Repair the worktree, then resume with --continue. After an independent rebase/reset, --reapply resets completed states and checks each patch against the current tree, skipping changes already present. The tool does not run git pull, perform a rebase, commit, stage, or execute source snippets; review each resulting diff and use the repository’s normal Git workflow.

The chat-code-patches skill documents this workflow for future agent sessions. Its retry/resume/reapply tests are in src/transform_md/tests/test_chat_code_blocks.py.

Ported Contracts¶

Signals.GrassmannianEBR contains finite algebraic models and explicitly conditional results:

  • The Pluecker lift of an affine 3D line satisfies the Klein relation, and the coordinate Hodge map is an involution preserving that residual.

  • The integral Schubert multiplication table gives the stated divisor-square and degree-four check figure.

  • The even-square p4m orbit-count arithmetic, layer-order product, and scalar Hooke energy drop are checked from their supplied formulas.

  • The McWeeny scalar polynomial fixes 0 and 1, moves values below/above 1/2 in the corresponding direction, and leaves 1/2 fixed. It is not a Birkhoff projection and does not eliminate every fractional value.

  • The two-reference energy inequality, two-phase step comparison, dispersion inequalities, reflection symmetry, and Jensen-Polya polynomial expansion hold only under their stated scalar assumptions.

The Rust finite_constraint_solvers module provides exact bounded references for N-Queens, proper graph colorings, a 9-by-9 Sudoku, and a 32-element D4/glide/ palette-transform family. Its Sinkhorn function performs a finite number of normalizations and is approximate in general. It does not claim general ARC-AGI solving, EBR convergence, DPP diversity guarantees, or physical symmetry.

These are mathematical or code-level contracts over supplied parameters. None of them confirms a physical realization, benchmark speed, materials property, zero-backaction operation, or energy efficiency measurement.

Explicit Exclusions¶

  • The proposed inference Landauer-Bures sum is not derived from the existing conditional Landauer contract; its QFIM-action term has no validated unit or thermodynamic premise here.

  • The proposed 490,000x and larger speedups combine assumed FLOPs, trajectory counts, and halting steps. No device-level profiling or accuracy-matched baseline was provided.

  • The G-EBR and DPP code does not establish that all trajectories reach distinct valid solutions. The exact N-Queens tests establish counts for the finite puzzle only; they do not establish EBR Pass@1 or Cov@20.

  • A symmetric transverse polynomial with positive supplied curvature does not prove the Riemann Hypothesis. The chat blocks do not establish positivity for the actual Jensen-Polya discriminant at every height.

  • The p6/mmm order product, QAHE Chern inputs, zero-resistance routing, sub-nanometer imaging, and knitted-fabric mechanics are not experimental measurements or validations in this port.

Only a conditional two-reference energy inequality is formalized; there is no NOCI or multi-reference SCF implementation.

Reproduce named molecules/geometries and basis sets with convergence, energy, and spin-contamination tolerances. The two-state identity alone does not establish a ground state. Chat: data/chats/Gemini_Quantum-Causal-Grassmannian-Monograph-Review_20261118-1629.md, lines 1943 and 2104.

RH locking

No RH-locking result is claimed; only finite reflection and polynomial identities are retained.

Treat positivity of the actual Jensen-Polya discriminant on the required domain as a separate analytic-number-theory problem. Formalize only independently established lemmas and assumptions.

Do not infer RH from a symmetric toy energy, finite determinant, analogy, or numerical zero search. Chat: data/chats/Gemini_Quantum-Causal-Grassmannian-Monograph-Review_20261118-1629.md, lines 2426, 2800, and 4841.

Dispersion physics

The sign trichotomy and scalar check figures are now proved; the physical correspondence is not.

Add units and a correctly typed real four-vector/Pluecker map with a fixed metric convention; prove the map preserves the quadratic form before labeling physical modes.

Algebraic signs remain abstract until polarization, frequency, wavevector, and boundary-condition measurements support a Maxwell/Proca/evanescent interpretation. Chat: data/chats/Gemini_Quantum-Causal-Grassmannian-Monograph-Review_20261118-1629.md, lines 1142 and 1240.

Porting Order¶

  1. Keep chat extraction source-ordered and content-hashed; automatically apply only reviewed unified-diff fences. Other code blocks remain artifacts until an owner and test are selected.

  2. Reuse existing Signals APIs before adding types. Add finite algebra with explicit assumptions to verified modules; put unvalidated physical premises in Signals.Pending with units, uncertainty, controls, and provenance.

  3. Keep exact N-Queens, graph-coloring, Sudoku, and finite-grid solvers as correctness baselines. Do not label their outputs EBR, DPP, 80-layer-group, or ARC-AGI benchmark performance.

  4. Add performance claims only after reproducible, accuracy-matched benchmarks on pinned datasets/hardware; add physical claims only after calibrated measurements and full energy accounting.
